# Application deployment and operations

This environment provides `appctl`, an installation-provided CLI, not an upstream Pi capability or skill. Read `/opt/devctl/DEPLOYMENT.md` before deploying or operating apps. Use `appctl --help` to discover deploy/list/status/logs/start/restart/stop/delete/verify. Build and review a dedicated artifact directory; never upload an entire repository, credentials or service data. All applications use `app-deploy.json`, listen on supplied HOST/PORT and write durable data to APP_DATA_DIR. The independent supervisor keeps enabled apps running without this session or development container. Stop preserves files and the app name; delete permanently erases artifacts, business data and logs and releases the name. Never delete without explicit user authorization and any necessary backup; deletion requires `appctl delete <app> --yes`. Start/restart reuse persisted artifacts and may briefly overlap old and new processes. Internal readiness and public checks are separate: DEPLOY_PUBLIC_URL is optional; if configured, run `appctl verify <app>` and inspect actual pages/resources. Otherwise state that public access is unverified. Applications in this installation share management access across projects; per-app runtime UIDs are not ownership boundaries. Coordinate changes to jointly used apps, and never modify host services or shared gateway configuration without explicit authorization. and never disclose keys, tokens or application secrets.
