# 静态网站发布

将当前项目已经准备好的静态文件发布到 `VIBE_PUBLIC_URL/<项目标识>/`。域名来自环境变量，不能写死在技能文件或脚本中。

## 目录边界

- 当前工作目录 `/workspace` 对应用户启动 `pi-docker` 时所在的宿主机目录。只处理当前项目，不得创建、清理或移动其他项目的文件。
- `/vibe-projects` 对应宿主机的独立静态发布目录。每个站点只占用 `/vibe-projects/<项目标识>/`，不得把源码直接放进这里。
- 不创建 `/vibe-projects/apps`、`/vibe-projects/public`、`/vibe-projects/.releases`。
- 域名根路径没有公开首页，返回 HTTP 403 属于当前站点约定；应验证项目路径而不是域名根路径。
- 项目标识只允许小写字母、数字及内部连字符，总长度 1～63 个字符。

## 发布流程

1. 确认当前项目及用户要发布的内容。检查技术栈、构建脚本、静态资源引用和路由方式，不要预设输出目录叫 `dist`。
2. 依据项目已有的构建脚本确定静态产物位置，不预设目录名；需要构建时优先遵循项目原有流程。构建工具对其**专用输出目录**的正常清理属于构建行为，不必一概禁止。但若输出位置已有用途不明或需要保留的文件，应先检查，避免擅自覆盖；无法确认时再向用户询问或选用独立输出路径。
3. 如果项目本身就是纯静态网站，且其中没有源码、依赖、凭据或其他不应公开的文件，可以显式选择该静态文件目录，无须额外构建。不要为了省事直接发布包含源码的项目根目录。
4. 确保站点基路径是 `/<项目标识>/`，资源地址使用正确的相对路径或显式前缀。当前 Web 服务器没有单页应用的重写回退，单页应用应考虑哈希路由。
5. 审查实际发布目录：应包含非空 `index.html`，不得包含凭据、环境文件、源码映射、项目源码和依赖管理文件。检查生成的 HTML、JavaScript、JSON 是否意外含有敏感数据，仅凭文件扩展名无法发现全部泄露。
6. 检查发布配置和挂载：

   ```sh
   printenv VIBE_PUBLIC_URL
   mountpoint -q /vibe-projects
   ```

   如果未配置发布功能，停止并提示用户在 `pi-docker` 仓库的 `.env` 中配置 `VIBE_PROJECTS_HOST_DIR`、`VIBE_PUBLIC_URL`，然后重新创建当前项目容器。
7. **显式传入已核实的静态目录**，不让发布脚本猜测来源。以下仅为命令示例：

   ```sh
   node /opt/pi-docker/skills/vibe-projects/scripts/publish.mjs example-site /workspace/构建产物目录
   ```

   脚本接受 `/workspace` 内的绝对路径或相对于当前目录的路径。脚本只复制文件到发布目录，绝不删除或更改发布源目录。
8. 发布会先将文件复制到临时目录，再替换相同项目标识下的旧站点。无发布历史、无版本回滚；替换期间可能存在短暂访问空窗，发生异常时应检查脚本输出。
9. 查看发布结果，必要时使用 `curl -I` 验证脚本输出的**项目完整网址**。如果 Cloudflare 质询或公网网络条件导致验证失败，应区分本地复制完成与公网可访问，不能声称验证成功。

## 安全约束

- 只发布可由浏览器直接访问的静态文件；不得开放服务端进程、容器管理接口或运行访客传入的命令。
- 不修改 Web 服务器、Cloudflare、Compose 配置或其他站点目录，除非用户明确要求。
- 发布脚本会阻止隐藏文件、符号链接、常见源代码和敏感配置文件，但它不能识别所有嵌入到构建结果中的秘密；人工审查仍然必要。
- 若已有发布目标是符号链接或非目录，脚本会拒绝覆盖，应先人工核实。
- 不要在 `/vibe-projects` 中存储项目源码、凭据、备份或临时工作文件。
