# 静态网站发布

将已审查的静态文件发布到 `VIBE_PUBLIC_URL/<项目标识>/`。域名只能来自环境变量，不得写死。文件保存于宿主机挂载，由外部静态 Web 服务器提供；Pi 容器停止后，已经发布的文件仍保留。

支持浏览器端 JavaScript、前端交互和 SPA；不托管 SSR、API、WebSocket、数据库等服务端进程，不把开发服务器当作持久部署。

## 边界

- `/workspace` 是当前项目，只处理用户授权的项目内容。
- `/vibe-projects` 是独立发布挂载；每个站点位于 `/vibe-projects/<项目标识>/`，不改动其他站点或自行增加全局目录结构。
- 项目标识只允许小写字母、数字及内部连字符，长度 1～63；确认覆盖目标属于当前项目后才能发布。
- 发布根目录是受信任的共享写入区，不提供站点级权限隔离。不要因能写入就修改其他站点，也不要将源码、凭据或备份放入该挂载。
- Web 服务器、DNS、TLS 应已在外部配置。未经用户明确要求，不修改 Web 服务器、Cloudflare 或 Compose 配置。
- 域名根路径是否返回首页、403 或 404 由外部服务器决定；始终验证项目完整路径。

## 流程

1. 检查项目技术栈、构建脚本和静态导出能力；不预设输出目录叫 `dist`。若项目需要服务端运行，应说明本 skill 不支持，不能声称已持久部署。
2. 遵循已有构建流程，确认并完成构建，再发布稳定的产物快照。构建工具可正常清理专用输出目录；若其中有用途不明或应保留的文件，先检查或询问，不擅自覆盖。
3. 显式选择静态产物目录。纯静态项目可以直接选择其静态目录，但不得为了省事发布包含源码、依赖、环境文件或项目元数据的根目录。
4. 检查 `/<项目标识>/` 子路径：按框架设置 Vite `base`、Webpack `publicPath` 或路由 `basename`；相对地址或带正确项目前缀的地址都可以。检查 HTML、CSS 和 JS 中的资源、链接、动态加载地址。只有已确认外部服务器支持 SPA 回退时才使用历史路由，否则使用哈希路由。
5. 审查实际产物：必须有非空普通文件 `index.html`，不能有符号链接、源码映射、凭据、环境文件、项目源码、依赖或备份。检查 HTML/JS/CSS/JSON 等内容是否嵌入敏感数据；文件名和特征扫描都不能替代人工审查。
6. 检查配置：

   ```sh
   printenv VIBE_PUBLIC_URL
   mountpoint -q /vibe-projects
   ```

   未启用时停止，提示在工具仓库 `.env` 中设置 `VIBE_PROJECTS_HOST_DIR`、`VIBE_PUBLIC_URL`，并在当前项目执行 `pi recreate`。发布目录须与项目、Pi 配置数据分离。
7. 显式传入已核实的静态目录：

   ```sh
   node /opt/pi-docker/skills/vibe-projects/scripts/publish.mjs example-site /workspace/实际产物目录
   ```

   目录参数可为 `/workspace` 内绝对路径或相对当前目录的路径。脚本只复制产物，不猜测输出目录，也不负责构建或启动服务端。
8. 检查输出。隐藏文件、符号链接、常见源码/敏感文件和高置信度凭据格式会在替换公开目录前阻止发布；疑似凭据字段、资源路径问题只提供提醒。出现疑似泄露时立即核实、移除并重发，必要时轮换已经公开的凭据。
9. 验证输出的完整项目网址，并抽查关键 JS、CSS、图片及路由。可以使用 `curl -I` 或 GET；状态码正确也不一定证明内容正确。若 Cloudflare 质询、登录页或网络条件妨碍验证，区分“本地文件已发布”和“公网已验证”，不得虚报成功。

## 发布行为

脚本先复制和检查私有暂存区，再替换同标识旧目录；替换期间可能有短暂空窗。正常切换失败会尝试恢复旧目录，但不提供历史版本或版本回滚；进程被强制终止时需要人工检查暂存区和锁。已有目标为符号链接或非目录时拒绝覆盖。

外部静态服务器必须禁止公开 `.publish-internal` 等隐藏路径、关闭目录列表且不执行服务端脚本。不要直接公开 `/workspace` 或开放容器管理接口。
